# CIGAR 0.14.2 performance iterations

## Baseline — retained 0.14.1

Created the branch from current remote main/release 0.14.1 without changing other
worktrees. Recorded ten real cold SDK calls and preserved a source-built baseline
worker with the existing release/features profile. Worker initialization dominates
the roughly 161 ms cold native query. Existing authored quality scores are 100/100.

## Iteration 1 — exact count-only tokenizer construction

The ordinary-counting API used a general CoreBPE that also constructs decoder,
special-token, sorted-encoding and 128 regex-thread structures. The candidate
loads the identical pinned vocabulary into one read-only encoder and uses the
same upstream regex and merge rules. Short pieces use the pinned public merge;
long pieces retain the upstream heap/rank/start behavior, counting surviving
tokens without building an unused decode result. Cache boundaries and limits,
tokenizer identity, graph selection and security controls are unchanged.

Added vocabulary-hash, reference-parity, long-input and concurrent-count tests.
The first test build exposed a SHA-256 test-format incompatibility with the pinned
sha2 release; the assertion now compares exact digest bytes. This was a test
compilation issue, not an observed engine result. Measurements and gate results
will be appended after executing the candidate.

The three new release-mode tests passed: pinned vocabulary identity, reference
parity for 2,028 Unicode/special/long/varied inputs, and eight-thread counting.
Ten real prototype calls measured median initialization 31.12 ms and cold
initialization/ingest/compile 33.56 ms, versus 154.14/161.29 ms in the retained
release baseline. Repeated compile median was 0.36 ms versus 0.79 ms. This is a
prototype profile, not yet the paired benchmark acceptance gate. The prototype
still negotiated 0.14.1; its exact binary and all raw observations are preserved.

## Iteration 2 — version integration and full verification

Kept the faster exact counter, advanced native/Python/TypeScript metadata together

and MIT notice suffix to release source capture so the new build inputs are bound.
Release tag gates target the new version without weakening their checks. Next:
paired benchmark, old-snapshot compatibility, full native/SDK boundary tests and
immutable patch security review.

The official packaged native build passed, including all context, broker,
persistence and snapshot tests. The first SDK test pass retained its failures:

No test assertion or security gate was removed. The first release test pass also
used macOS LibreSSL without Ed25519 support; rerun with the existing OpenSSL 3

Extended reference parity to 2,040 cases with mixed long alphabetic/punctuation

that changing the embedded vocabulary invalidates the release source binding.
Added an executable compatibility check using the unchanged release corpus,
complete outputs and bidirectional snapshot/delta verification. Final paired
measurement and SDK results are pending.

## Iteration 3 — checked merge invariants

The strict Clippy gate rejected unchecked indexing in the upstream-derived heap
loop (the repository already denies `indexing_slicing`). Replaced direct indexing
with checked access, used byte windows for initial pairs, checked the surviving
token decrement, and made an inconsistent neighbor invariant return `Tokenizer`
instead of relying on a debug assertion. No lint allowance was introduced.
Clippy now passes with `-D warnings` across all context targets/features.

The clean packaged iteration-2 worker passed native tests. Its Python SDK passed
523 tests plus 39 subtests with zero skips once both real and stalled workers were
supplied. Release integrity checks passed 74 tests plus 96 subtests using OpenSSL
3; core-only tests also passed. The final measurement will use the newly packaged
iteration-3 worker after rechecking the expanded parity corpus and SDK boundaries.

## Iteration 4 — immutable vocabulary prepared at build time

The user requested continued work toward within 2× the fastest competitor;
the separate parity protocol records the new target and primary matrix. Fresh
baseline `cigar-parity-baseline-001` ran all three libraries: 86 harness tests,
162 cells and both replays passed. Graph medians at 2048 were CIGAR 89.95 ms,
NetworkX 4.56 ms and rustworkx 6.90 ms; the previous 50% gain did not meet parity.

The build now checks the exact source SHA-256, all ranks, duplicate/empty tokens
and byte coverage, then emits a deterministic little-endian static lookup table.
Runtime lookup uses exact bytes, a fixed maximum successful probe count and checked
offsets, with no runtime map construction or vocabulary I/O. Hashes are lookup
accelerators, not token identities or authentication. The platform-independent
hash/format supports cross-compilation without host-endian table assumptions.
Short and long merges retain upstream greedy/rank/leftmost behavior; short work
is bounded below 100 bytes and long work retains the heap. Text caches are still
per-instance and bounded. Build inputs remain source-bound and packaged.

All 199,998 token/rank lookups and the existing 2,040 upstream count cases passed.
All 149 native tests passed (the existing ignored crash child is called by its
parent); all 172 compatibility cases and bidirectional snapshot/delta pairs match
the retained 0.14.2 candidate. Clippy first rejected a needless vector in the new
test; it now uses the direct array and strict Clippy passes without exceptions.

## Iteration 5 — precompiled ordinary segmentation

Replaced runtime regex construction with a build-time DFA over the exact pinned
regular alternatives. The small whitespace lookahead rule preserves the original
negative-lookahead boundary. The runtime uses the fully checked sparse DFA loader;
no unchecked loading or input-dependent validation is omitted. The embedded table
is target-endian and construction uses bounded DFA/determinization memory.

All 21,080 exact segment-boundary comparisons, the 2,040 count oracle corpus,
concurrent counting, all vocabulary ranks and strict Clippy pass. The full native
suite passes. The retained prototype is
`0fbfe3937daed0e904e2bc82eaaffc3f59b8d2d62630e08e4a90ddf28135649b`.
Session `cigar-parity-i05-001` passed 86 harness tests, all 162 cells and both
replays. Its 2048 smoke medians were 63.70 / 5.25 / 5.01 ms (CIGAR / NetworkX /
rustworkx); graph medians were 56.85 / 7.05 / 6.50 ms. These diagnostic results do
not meet parity. A brief diagnostic Rust link overlapped the final cells; no final
acceptance decision uses this intermediate run. A separate native diagnostic
measured about 1 ms tokenizer initialization and 8 ms complete process launch.

## Iteration 6 — cleanup order under the unchanged deadline

An actual retained-query profile observed time spent in Popen's timed wait
polling before the worker's I/O thread joined. Cleanup now kills the process,
wakes and joins its pipe-owning thread, then reaps the process, sharing the same
five-second absolute deadline. Failed cleanup remains retryable; fork/PID checks,
stream ownership, process isolation and descriptor closure are unchanged.

The complete Python suite passes: 523 tests and 39 subtests, zero skips. This
includes process death, stalled writes, deadlines, concurrent close, forked locks,
cleanup failures, and all public signatures/types. Frozen candidate session
`cigar-parity-i06-001` is collecting all three libraries. The 2× gate is pending.

## Iteration 7 — rejected Darwin launcher prototype

Tested an atomic-close Darwin public spawn prototype without changing grading or

The cProfile traces aggregate overlapping thread activity and are not phase-wall
measurements; retain them as diagnostics only. The replacement diagnostic records
main-thread perf-counter spans around import, launch, individual calls and close.

## Iteration 8 — serialized deadline-aware POSIX pipe I/O

Retains standard subprocess creation, close_fds=True, version negotiation and
process isolation. POSIX poll/nonblocking I/O avoids per-request Python thread
handoffs; unsupported platforms retain the original bounded threaded transport.
Each call duplicates its pipe descriptors under the close lock and owns those
leases until completion. Concurrent close cannot redirect I/O to a reused host
descriptor. Unused buffered originals are safe to close without another thread
holding their internal locks. Existing in-flight replies may complete during
close, as before; future calls fail Closed.

Review caught and corrected interrupted partial-I/O stream reuse and poll's
signed-int timeout limit. Interrupted I/O poisons/closes the channel while keeping
the original exception; long accepted timeouts use clamped poll intervals under
the original deadline. Lease-lock contention is bounded and returns Busy before
dispatch. Native byte caps, framing, decoder correlation and fork checks remain.

All 536 Python tests and 39 subtests pass with zero skips. New real-pipe checks
cover fragments, partial/invalid/extra replies, exact multi-chunk limits, blocked
writes, descriptor reuse during close, interrupted writes and TIMEOUT_MAX.
Original queue fault injections explicitly cover the portable backend; the seven
broker malformed decoder cases now inject at the common exchange seam. No fault
case is removed. Strict Ruff/mypy pass. Dashboard comparison
`cigar-parity-i08-001` is collecting the next 54-cell diagnostic matrix.
