# CIGAR 0.14.2 performance results

The local candidate meets the declared 50% query-latency target. Across the fixed
18-task study, the median of task medians fell **55.24%**, from **186.74 ms to
83.59 ms**. The mean of task medians fell **57.60%**. All 270 paired response
envelopes matched exactly, including native rendering, snapshots, token counts,
citations and refusal codes. Authored evidence and graph scores remain 100/100.

This is a local, unpublished candidate on `codex/cigar-0.14.2-speed`, based on
fetched main/release `10dd521dec8224d0957365a90111158e43c9d87f`. The measured
implementation is `68dca4467b035e7209ccda3c8015c0eaedbb9bd7`; subsequent report
commits record evidence without changing that implementation.

## Measured result and boundary

The [protocol](0.14.2-protocol.md) was recorded before the paired study. The
unchanged Context Graph Benchmark 0.2.0.dev3 adapter rebuilds a trusted authorized
native graph inside each query. Timing includes its query-side SDK import, native
worker initialization, document/relationship ingestion, compilation and cleanup.
Initialization was not moved into a separate unmeasured phase.

Both existing suites ran at 512/2048/4096 tokens with five fresh-process
repetitions, seed `20261106`, and rotating adjacent version order: **540 original
cells**. There were no failed, timed-out, unsupported or discarded cells. Correct
negative cases returned the same refusal. Builds and SDK test suites had finished
before the paired measurement. The machine remained a normal shared macOS host.

## What changed

Profiling showed that general tokenizer construction dominated cold queries. It
loaded decoding, special-token, sorted-token and 128 per-thread regex structures
unused by CIGAR's ordinary-counting API. The new private counter constructs the
read-only ordinary encoder and one regex. It uses the same pinned vocabulary and
regex, short-piece splitter, and rank/start heap merge for long pieces, counting
surviving tokens without constructing unused decoded output.

The long-piece merge uses checked access and fail-closed invariant errors. The
public tokenizer identity remains `o200k_base.tiktoken-rs-0.12.0.ordinary` because
the vocabulary and ordinary-token semantics are preserved. Exact-text cache
bounds, clear-generation protection, privacy ownership, graph selection, hard
closure, authorization, input/aggregate limits, deadlines and the v1 protocol/ABI
are retained. Native/Python/TypeScript version metadata advances together.

The [iteration journal](0.14.2-iterations.md) explains the initial profile,
prototype, version/setup corrections, strict lint failure and checked merge fix.
The embedded vocabulary is byte-for-byte equal to pinned tiktoken-rs 0.12.0:
199,998 entries, 3,613,922 bytes, SHA-256
`446a9538cb6c348e3516120d7c08b09f57c36495e2acfffe59a5bf8b0cfb1a2d`.
Its MIT notice is included in the crate and SDK notices; release source capture
now binds the vocabulary.

The fixture quality score already reached its ceiling on 0.14.1. The improvement
is faster delivery of exactly the same outputs, without changing scoring or gold
data. These authored suites share one dependent quality cluster; process
repetitions do not create independent effectiveness evidence. The reports retain
`comparative_qualified:false`; annotation precision of 0.60 on graph fixtures is
also unchanged and is not a reliable broad semantic-quality estimate. New quality
claims need separately annotated, diverse held-out corpora and task outcomes.

Execution was local macOS ARM64. Seven-platform builds, independent clean-build
agreement, release signing and registry publication remain separate release
work. The candidate build correctly records `release_ready:false`.
