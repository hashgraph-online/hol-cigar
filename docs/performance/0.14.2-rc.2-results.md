## Scope and changes

RC2 adds owner-bound, atomic ticket consumption in Rust, Python and TypeScript,
advertised as `consume_ticket.v1`. Existing authority, source provenance, grant,
expiry and evidence checks run before removal under exclusive broker ownership.
It avoids two agent round trips and the intervening source-update window. It
does not certify model answers or authorize external effects. Uncertain outcomes
are never retried. Other APIs and the portable transport remain available.

The measured system also uses a separately identified common reader treatment,
`structured-evidence.v6`, with lossless evidence/citations and question-scoped
handoffs. Role instructions distinguish a missing requested fact from a known
false policy condition. An explicitly isolated library cohort gives the reader
uncontended execution, with all tasks and the full standard schedule retained.
The Qwen3.8-27B 8-bit weights, greedy settings, 128-token generation limit and
fresh-cache policy remain unchanged. All actual input/output tokens count.

The historical shared-reader result remains 63.21 overall / 25% workflow. Changed
reader instructions and contention mean this result cannot be attributed solely
to engine code or compared as a matched speed/quality gain against those older
competitor hours. Reader development used the public authored tasks, including
abstentions. There is no held-out generalization or industry qualification claim.
