## Engineering loop and gates

Each code iteration records cause, source/worker identity, change, tests and
actual benchmark results in the engine journal and dashboard Project changes.
Each measured candidate gets a fresh SDK/worker descriptor and session; never
overwrite a previous candidate or silently retry an unfavorable measurement.

Before ranking a candidate: verify exact pinned vocabulary/ranks, upstream token
parity, long-piece complexity, bounded per-instance caches and generation clears,
unchanged snapshot/delta identity, full release-case compatibility and exact
existing benchmark response envelopes. Run native/SDK/security boundary checks
affected by the change and the existing strict lint gates. Finalize with the
official packaged native build and a review of the immutable final code diff.
Preserve process isolation, byte/work/budget limits, authentication, authority,
deadlines, fork ownership and worker integrity verification. Build-time preparation
may only replace work on immutable source-bound data, never input-dependent checks.

The existing dashboard loop remains bounded and applies no harness edits for a
valid low score or expected refusal. Code refinement in this task is attributed
to the current coding agent, not falsely labeled as a successful automatic driver
repair. Keep the PR in draft while engineering continues and leave it unmerged.
