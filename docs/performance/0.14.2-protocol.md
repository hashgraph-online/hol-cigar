# CIGAR 0.14.2 query performance protocol

Branch: `codex/cigar-0.14.2-speed`, created from fetched `origin/main`, commit
`10dd521dec8224d0957365a90111158e43c9d87f` (the 0.14.1 release).

The existing authored graph fixture reaches 100/100 evidence/graph scores on 0.14.1.
Those scores are correctness gates. They will not be raised by changing labels,
grading, budgets, input filtering, or the shared benchmark adapter.

## Timing target

Compare the retained 0.14.1 release SDK/worker against the source-built 0.14.2
candidate with the same native features, release optimization, workload, adapter,
counter, and machine. Use both existing smoke/graph suites, all 18 tasks, budgets
512/2048/4096, five fresh-process repetitions, a fixed recorded seed and rotating
treatment order: 540 original cells across the two versions. Preserve failures.

Primary: at budget 2048, compute each task's median query time across repetitions,
then the median and mean of those 18 task medians. Both must fall at least 50%.
Also report all budgets, useful and refusal cases separately, p95, process startup
and whole-cell timing. Do not transfer initialization from query to an unmeasured
phase. Query time includes SDK import, native worker initialization, authorized
graph construction, compilation and cleanup, as in the existing adapter.

The independent benchmark process/counter startup is not CIGAR query time and
remains reported separately. Repeated timings are process measurements, not
independent quality evidence. These authored data have one quality cluster.

## Correctness, compatibility and security gates

- Preserve exact ordinary o200k counts, tokenizer identity, rendered context,
  citations, evidence/graph scores, refusal behavior and capability coverage.
- Compare baseline/candidate response payloads for matching tasks/budgets, retaining
  original envelopes and artifact hashes. No removed or retried unfavorable cells.
- Exercise upstream tokenizer parity on Unicode, special-token lookalikes,
  deterministic varied inputs, long pieces and concurrent calls. Keep heap merging
  for long pieces; never introduce quadratic work on attacker-controlled strings.
- Run native context, snapshot/delta, budget, broker/persistence and SDK boundary
  tests, plus release/version checks. Keep authorization, input/aggregate limits,
  exact budget accounting, deadlines, fork safety and bounded cache clearing.
- Review the immutable final diff using Codex Security. Record its actual scope,
  outcome and any verification limits; a local test pass is not a proof of security.

## Initial profile

Ten real cold 0.14.1 SDK/worker calls measured median initialization 154.14 ms,
ingest 5.81 ms and compile 1.38 ms. Median cold initialization+ingest+compile was
161.29 ms; SDK import was separately 32.87 ms. The retained profile includes raw
timings, actual snapshots, negotiated version and cleanup status. This motivates
removing unused tokenizer construction work, while keeping the exact tokenizer
algorithm/vocabulary and graph functionality.
