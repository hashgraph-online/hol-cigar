## Security and remaining limits

Completed immutable implementation reviews `3b944fe4-e953-463e-af95-07d66de486bb`
and `05daab78-b1ef-4fad-a07d-a2e4a171ba80` cover the performance implementation
and star-export correction, with zero confirmed findings. Final native adapter
review `9590ccb7-6dc0-4669-a086-b9bc0d7b0db2` covers all three frozen component
files, with independent baseline, architecture and focused filter reasoning.
It also has zero confirmed findings and no snapshot-change warning. The earlier
adapter scan began before final parser caps; it is retained separately and was
superseded by this exact-source review after its snapshot warning.

The native adapter forbids unsafe Rust and has no subprocess, network or locator
opening path. It uses duplicate-rejecting closed JSON shapes, 8 MiB frame/output,
128 MiB cumulative input, depth/collection limits and runner-enforced deadlines.
It is a trusted local host adapter, not authenticated brokerage or an OS sandbox.
Existing engine authentication, authority, byte/work/cache limits, fork ownership,
worker integrity and snapshot controls remain in the reviewed engine paths.

Two inherited profile limitations are explicit. Supplied relationships are linked
only when their `from` endpoint is visible; an incoming contradiction from a
hidden source is omitted before native symmetric linking. Also, verifying native
snapshot token counts does not prove the converted neutral citation rendering
fits the same budget. The unchanged independent evaluator recounts that rendering
and rejects excess. Both behaviors are shared by the retained Python profile;
no additional confidentiality bypass was established. The current fixtures show
no violation, but do not prove those representations universally equivalent.

Hosted strict Rust and Python portable-package jobs passed on the measured code.
Other repository CI is **not green**: source/coverage jobs lack their required
protected tool-input manifest, broader dependency policies fail, and pnpm audit
hydration reports a pinned-distribution digest mismatch. Those controls were not
bypassed or weakened. The npm readiness version route omitted 0.14.2; a follow-up
adds it to the existing stable qualification path, retaining exact-version
rejection and tag-only publication guards. Whole-repository release qualification
remains open. None of the dependency-policy flagged package identities occurs
in the measured native adapter's pinned registry set. This does not establish
repository-wide security or universal vulnerability absence.

The final adapter scan reports 1,578,860 cumulative rollout tokens, including
1,540,480 cached input tokens. These conversation counters overlap prior work
and are not isolated scan cost. Other-platform execution, hermetic/compiler
attestation and independent clean-build agreement remain unverified.
