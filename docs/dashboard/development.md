# Dashboard development

The dashboard is split into independently testable optional components:

- `crates/cigar-dashboard`: local configuration, verified assets, authentication, typed daemon
  gateway, content-safe status/events, dashboard SQLite, macOS run supervision, and receipt checks;
- `crates/cigar-soak`: deterministic soak plan and offline result verification; no workload driver;
- `apps/dashboard`: dependency-free CSP-compatible application and pure policy/model tests;
- `schemas/dashboard`: closed configuration/API/run/product/supervisor receipt contracts;
- `tests/dashboard`: fixtures, reviewed profiles, schema checks, and security cases.

Cargo `default-members` remain the CLI, daemon, and MCP packages. Root pnpm scripts do not build the
dashboard. Work on this tree without resetting or reformatting unrelated changes.

## Deterministic frontend workflow

The browser source is plain ES modules and CSS under `apps/dashboard/public`; there is no runtime npm
dependency or bundler. Every served file is an explicit asset.

```sh
pnpm --filter @cigar/dashboard build
pnpm --filter @cigar/dashboard test
```

`build` recursively inventories ordinary non-symlink files, rejects source maps, dot paths and
unknown extensions, then writes sorted canonical size/MIME/SHA-256 bindings to
`asset-manifest.v1.json`. The verifier recomputes the complete inventory independently. Never hand
edit the digest manifest or add inline scripts/styles to bypass CSP.

Browser-facing data must pass closed validators before rendering. Use `textContent`/DOM creation,
never HTML injection. Status needs text or an accessible label in addition to color. Preserve the
table/text equivalent for diagrams, visible focus, reduced-motion behavior, and the 320 px layout.
Pure tests are necessary but do not replace the deferred real-browser accessibility/visual gates.

## Schema and generated protocol workflow

```sh
python3 tests/dashboard/validate_schemas.py
cargo test --locked --offline -p cigar-dashboard protocol::tests
pnpm --filter @cigar/dashboard test:status
```

Dashboard schemas are strict local documents: stable `$id`, local-only `$ref`, closed object keys,
and bounded text/arrays/numbers. Add a schema to the scan rather than fetching a remote reference.

The browser protocol catalog is generated by the repository interface projection from the frozen
operation, payload, and error catalogs. It must retain exactly seven services, 45 operations, 34
public error records, and the request/response/event field and size metadata. Do not create a second
operation list in UI code. Regenerate through the authoritative xtask projection and review both the
Rust embedded JSON and browser validator tests.

## Sidecar gates

```sh
cargo fmt --package cigar-dashboard -- --check
cargo test --locked --offline -p cigar-dashboard --all-targets
cargo clippy --locked --offline -p cigar-dashboard --all-targets --all-features -- -D warnings
RUSTDOCFLAGS='-D warnings' cargo doc --locked --offline -p cigar-dashboard --no-deps
```

Keep `unsafe_code = "forbid"`. Do not introduce direct daemon/store dependencies, a generic upstream
proxy, shell invocation, output rendering, or a fallback that weakens owner/path/receipt checks.

## Adding a reviewed run profile

1. Add the profile in ascending ID order and update the exact registry source revision.
2. Use an allowlisted executable selector and fixed argv. Browser-provided flags, paths, cwd,
   environment, durations, network modes, or evidence categories are prohibited.
3. Provide honest expected/max duration, memory/process metadata, output/evidence bytes, fixed
   network/concurrency class, cancellation grace, platform set, and documentation.
4. Define a deterministic receipt filename and implemented product receipt schema. A command that
   only exits zero remains `command_not_implemented`.
5. Verify the command writes create-new canonical content-free evidence below
   `CIGAR_EVIDENCE_DIR` and does not pass that location or the daemon token to its own test cases.
6. Add positive launch/receipt and negative missing, malformed, wrongly bound, symlink/hard-link,
   outcome-mismatch, cancellation, timeout, and capacity tests.
7. Keep soak profiles unavailable until an isolated installed-binary driver exists. Do not target
   the observed daemon or user data.
8. Run schema, browser, Rust, strict lint, and documentation gates. Record exact receipts before
   changing `availability_state` to `available`.

The current supervisor's claim is native Apple-silicon macOS only. Generation-1 running/cancelling
rows have fail-closed PID/PGID/start-identity reconciliation. SQLite v4 transactionally reserves and
settles exact aggregate output/evidence bytes with terminal state and sanitized descriptors. The
child-only launcher hard-limits core dumps, CPU time, per-file size, and open descriptors; aggregate
RSS and process-group membership are sampled every 100 ms and fail closed, but are not kernel-hard
job limits. Automatic adoption, interrupted-preparing repair, exhaustive child-escape handling,
cross-platform process control, structured progress, and destructive full-volume recovery testing
still require separate design/evidence; do not simulate support with platform skips.
